🔧 Common Issues & Fixes
FIXED Qdrant unhealthy (your current error)
The Qdrant health check endpoint was wrong. Already fixed in the latest zip — just re-run setup. Or fix immediately by running:
docker compose up -d qdrantForce restart Qdrant
docker compose logs qdrantCheck why it failed
ISSUE Frontend shows blank page or loading forever
Next.js needs to compile on first start. Wait 60 seconds, then refresh. If still blank, check the frontend logs:
docker compose logs -f frontend
Look for: ✓ Ready in Xs — once you see that, refresh the browser.
If you see npm ERR! — run the npm fix below.
docker compose exec frontend npm installFix missing packages
docker compose restart frontend
ISSUE No articles appearing after 15 minutes
The RSS agent may have crashed. Check its logs and restart it:
docker compose logs agent-rss-feed --tail=30
docker compose restart agent-rss-feed agent-web-crawler
Also check the database has articles: open localhost:8000/api/feed?limit=3
ISSUE Port already in use (3000, 8000, etc.)
Something else is using that port. Find and stop it:
netstat -ano | findstr :3000Find what's on port 3000
taskkill /PID [PID_FROM_ABOVE] /FKill the process
Or change the port in docker-compose.yml: "3001:3000" → access at localhost:3001
ISSUE Out of disk space / Docker uses too much disk
docker system dfSee disk usage
docker system prune -fClean unused images/containers
ISSUE Elasticsearch not starting (out of memory)
Elasticsearch needs at least 2GB RAM. On Windows, increase Docker Desktop memory: Docker Desktop → Settings → Resources → Memory → set to 8GB+
docker compose logs elasticsearch --tail=20
NUCLEAR Complete reset — start fresh
⚠ This deletes ALL data (articles, database, etc.)
docker compose down -v --remove-orphansDelete containers + volumes
py scripts/setup.pyFresh setup
📊 What to monitor and where
1
RabbitMQ — Pipeline health
Open localhost:15672 → Queues tab
Green: All queue depths near 0, no DLQ messages
Warning: verify.claims > 100 (verification backlog)
Alert: Any dlq.* queue has messages (processing failures)
2
API health check
Open localhost:8000/ — should return {"status":"ok"}
Open localhost:8000/api/stats — see live article counts
Open localhost:8000/api/metrics/pipeline — pipeline metrics
3
Grafana dashboards
Open localhost:3003 (admin / admin)
→ Dashboards → Browse → Import dashboard from deploy/grafana/ (if added)
Key metrics: articles/hour, truth score distribution, queue depths, API latency
4
Database article counts
docker compose exec -T postgres psql -U dhara -d dhara -c "SELECT status, COUNT(*), ROUND(AVG(truth_score),1) as avg_score FROM story_clusters GROUP BY status ORDER BY count DESC;"
